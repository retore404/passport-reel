# Design

## Context

- リポジトリには開発ツール（pnpm workspace、oxlint、oxfmt、knip、vitest）だけがあり、アプリケーションのパッケージはまだない。`pnpm-workspace.yaml` の `packages` は空で、`.oxlintrc.jsonc` には「技術スタック確定時にフレームワーク向けプラグインを追加する」とコメントがある。
- 後続の issue で、この地図描画を時系列アニメーション（#3、縦長 9:16）と動画書き出し（#5）に使う。動画書き出しでは、時刻 t を与えてフレームを1枚ずつ描く方式を採る想定である。このため、地図描画は**同期的かつ決定的**である必要がある。
- フロントエンドのみで完結させる。サーバー、外部 API、API キーは使わない。

## Goals / Non-Goals

**Goals:**

- `apps/web` に、静的ビルド可能な Web アプリの基盤を置く。
- 訪問国の集合を受け取って Canvas に平面世界地図を描く描画関数を用意する。この関数は後続のアニメーションと動画書き出しで再利用できる形にする。
- `pnpm check` がアプリを含めて通る状態にする。

**Non-Goals:**

- 9:16 のレイアウト、年や累計などの文字表示、アニメーション（#3）
- 訪問データの入力・保存、国名の日本語表示（#6）
- 地球儀表現（#7）
- デプロイ先の設定や CI の構築

## Decisions

### D1. パッケージ構成: `apps/web` に Vite + React + TypeScript

- 静的ファイルを出力でき、開発サーバーも軽い Vite を使う。
- 後続で入力フォームや一覧などの UI が増えるため、UI フレームワークとして React を採用する。地図そのものは React の外にある Canvas 描画関数が担い、React は Canvas 要素とデータの受け渡しだけを持つ。
- 代替案: フレームワークなしの素の TypeScript。今回の地図表示だけなら十分だが、#6 の入力 UI で結局フレームワークが必要になるため見送る。Svelte も候補だったが、エコシステムと lint プラグインの成熟度で React を選ぶ。
- 型検査は、パッケージ側の `typecheck` スクリプトから、ルートの `pnpm typecheck`（`pnpm -r --if-present typecheck`）経由で実行する。
- `.oxlintrc.jsonc` に `react`（hooks のルールを含む）と `jsx-a11y` プラグインを追加する。

### D2. 描画: d3-geo + Canvas 2D、投影法はメルカトル（北緯84度〜南緯70度）

- `d3-geo` の `geoPath` に Canvas の 2D コンテキストを渡して描く。描画は同期的に完了するので、同じ入力からは常に同じフレームが得られる。後で `frame(t)` から呼び出せる。
- 投影法は `geoMercator`。一般的なウェブ地図と同じで見慣れていることを優先する。また、上下を切ったメルカトルは横:縦がおよそ 1.34:1 と縦に高く、縦長の動画（#3）の画面を広く使える。
- メルカトルは極に近づくほど無限に引き伸ばされるため、表示する緯度を北緯 84 度（グリーンランドの北端まで）〜南緯 70 度に限る。南緯 60 度で切ると南極が丸ごと消え、AQ を訪問済みにしても表示されないので、沿岸部が残る南緯 70 度にする。この範囲が Canvas にちょうど収まるよう `fitSize` でスケールし、範囲外は `clipExtent` で切る。Canvas の縦横比も同じ範囲から計算する。
- 代替案: `geoNaturalEarth1` は面積の歪みが小さいが、見慣れない形であることと、横長（約 1.95:1）で縦長画面と相性が悪いことから見送った。メルカトルでは高緯度の国（ロシア、カナダ、北欧など）が実際より大きく塗られるが、これは許容する。
- 描画関数の入力は「描画先のコンテキスト・サイズ・地図データ・訪問国の集合」だけにし、DOM や React の状態には依存させない。地図データの読み込み（非同期）は描画関数の外で一度だけ行う。
- 代替案: MapLibre などのタイル地図はタイルの読み込みが非同期で、フレームを確定的に描けないため却下した。SVG は動画へのキャプチャが難しいため却下した。

### D3. 国境データ: `world-atlas` の `countries-50m.json` を同梱

- Natural Earth を TopoJSON 化した `world-atlas` を依存に入れ、ビルドに同梱する。外部への通信は発生しない。
- `countries-110m` には SG、MC、VA、MV、BH、MT、LI、AD、SM、HK、MO の形状がないことを確認した。50m にはこれらが含まれている。小さな国も「訪問済みとして示す」ことがこの機能の要件なので、50m を採用する。サイズは約 756KB（圧縮前）で、地図の読み込みが一度で済むなら許容範囲と判断した。
- 地図データは動的 import で読み込み、最初の JS バンドルと分ける。

### D4. 国の識別: ISO 3166-1 alpha-2 を外部との契約にし、numeric からの変換は `i18n-iso-countries` を使う

- `world-atlas` の国の id は ISO 3166-1 numeric（例: `"392"`）である。一方、アプリ内と後続の保存データでは、人が読める alpha-2（例: `JP`）を使う。
- 変換には `i18n-iso-countries` の `numericToAlpha2` を使う。#6 で国の一覧（alpha-2 の全件）が必要になるときにも同じライブラリを再利用できる。国名の表示には `Intl.DisplayNames` を使う予定なので、このライブラリのロケールデータは登録しない。
- id のない形状（Kosovo、N. Cyprus、Somaliland、Indian Ocean Ter.、Siachen Glacier）は、どの alpha-2 にも対応しない陸地として、常に未訪問の色で描く。
- 代替案: numeric と alpha-2 の対応表を自前で持つ。約 250 件を手で保守することになり、ISO の改訂に追随する手間がかかるため見送った。

### D5. 小さな国の判定: 投影後の面積で判定してマーカーを描く

- 描画するたびに、各国の投影後の面積（`geoPath.area`、単位は px²）を計算する。しきい値未満の訪問国には、`geoPath.centroid` の位置に円形のマーカーを描く。
- Canvas のサイズによって「小さく見えるかどうか」が変わるので、固定の国リストではなく表示サイズに対する面積で判定する。将来ズームや地球儀にしても同じ考え方が使える。
- しきい値は描画関数の定数にし、実際の表示を見て調整する。
- 飛び地などで重心が陸地から外れる国（複数のポリゴンからなる国）は、最大のポリゴンの重心を使う。
- 国境データには、同じ国コードの形状が別々に入っていることがある（例: AU の本土とアシュモア・カルティエ諸島）。そのため面積は形状ごとではなく、国コードごとに合算して判定する。こうしないと、大きな国に属する小さな離島にマーカーが出てしまう。

### D6. サンプルデータ

- 訪問データの入力（#6）ができるまでは、アプリに同梱した固定のサンプル（大きな国、小さな国、飛び地を持つ国を含む alpha-2 の集合）を描画する。
- サンプルは描画関数の外のモジュールに置き、#6 で置き換えやすくする。

### D7. テスト方針

- 純粋なロジックは vitest（node 環境）で単体テストする。対象は、numeric から alpha-2 への変換と id のない形状の扱い、訪問国の集合と地図の国の照合（未知コードを無視すること）、面積しきい値によるマーカー対象の判定。
- Canvas への描画結果そのものは、描画呼び出しを記録するフェイクのコンテキストで「どの国をどの色で塗ったか」「どこにマーカーを描いたか」を検証する。ピクセル単位の比較はしない。
- 見た目の最終確認は、ユーザーに開発サーバーを起動してもらってブラウザで行う。

## Risks / Trade-offs

- [50m の国境データが重く、初回表示が遅い] → 動的 import でバンドルを分割する。体感上問題があれば、後で TopoJSON の簡略化（`topojson-simplify`）を検討する。
- [ISO 3166-1 にあるのに地図に形状がない国が残る可能性がある（例: 一部の海外領土）] → 実装時に、`i18n-iso-countries` の alpha-2 全件と地図の形状を突き合わせ、形状のないコードを洗い出す。結果は #6（国の選択肢）の判断材料として issue に残す。本変更では、spec の「地図に存在しない国コードの扱い」に従って無視する。
- [Kosovo などは ISO の番号がなく、ハイライトできない] → 本変更では未訪問の陸地として描く。対応が必要になったら、名前などで別の識別子を割り当てる変更を別途起こす。
- [国境の描き方には政治的な判断が含まれる] → Natural Earth の描き方をそのまま採用し、アプリとして独自の判断は加えない。
- [複数のポリゴンからなる国の重心が不自然な位置になる] → D5 のとおり最大のポリゴンを使い、テストで確認する。
