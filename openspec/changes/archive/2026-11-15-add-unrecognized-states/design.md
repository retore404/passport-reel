# Design

## Context

- 国名は `records/countryNames.ts` が i18n-iso-countries の日本語データから作っている。このデータには `XK`「コソボ」が含まれるが、北キプロスとソマリランドは含まれない。
- 地図の形状は `map/countries.ts` が world-atlas（countries-50m）から作り、ISO 3166-1 numeric の `id` を alpha-2 に変換している。コソボ・北キプロス・ソマリランドの形状には `id` がない（`properties.name` が `Kosovo`・`N. Cyprus`・`Somaliland`）。そのため `alpha2` が `undefined` になり、どの記録とも一致しない。3つとも親国（Cyprus・Somalia）とは別の形状として収録されているので、親国から切り出す処理はいらない。
- 保存形式（version 1）は国を `/^[A-Z]{2}$/` で検証している。2文字の ID ならそのまま保存・復元できる。
- 国コードのバッジは、記録の一覧（`RecordList.tsx`）と国の候補（`RecordForm.tsx`）の2か所にある。動画とプレビューには国名だけが出ている。

## Goals / Non-Goals

**Goals:**

- 対象地域の一覧（ID・日本語名・国コードの表示・地図データでの形状の名前）をコード上の1か所に定義し、国名と地図の両方がそれを参照する。
- 一覧と地図データが食い違ったときに、テストで気づけるようにする。

**Non-Goals:**

- 親国の形状から地域を切り出す仕組み。#39 で必要になったときに、一覧の1件ごとの「形状の見つけ方」に種類を足して対応する。
- `MapCountry.alpha2` などの名前の変更。この値はすでに ISO にない `XK` を含みうる。名前は変えず、コメントで「alpha-2 または ISO 3166-1 にない地域の ID」と説明する。

## Decisions

### 対象地域の一覧を `records/unrecognizedStates.ts` に置く

一覧の正は `visit-records` の仕様なので、コード上の定義も `records/` に置き、`map/countries.ts` から参照する。定義には、正が `openspec/specs/visit-records/spec.md` の「国として扱う ISO 3166-1 にない地域」であることをコメントで書く。

各要素には `code`（ID）、`name`（日本語名）、`displayCode`（`"XK"` か `"--"`）、`mapName`（world-atlas の `properties.name`）を持たせる。

- 代案：`map/` に置く。地図側から見ると自然だが、一覧の正（visit-records）と置き場所がずれる。
- 代案：`src/` の直下に共通のモジュールを新しく作る。参照するのが2か所だけなので、まだ層を増やすほどではない。

### 国コードの表示は一覧に明示し、仕様のルールとの整合をテストで確かめる

`displayCode` を表示のたびに i18n-iso-countries から求めるのではなく、一覧に書いておく。そのうえで、「`displayCode` が ID と同じ値になるのは、i18n-iso-countries の日本語データにその ID が収録されている地域だけで、それ以外は `--` になる」ことを単体テストで確かめる。

`countryNames.ts` に、表示用の国コードを返す関数を足す。一覧にあるコードには `displayCode` を返し、それ以外のコードにはコードをそのまま返す。`RecordList.tsx` と `RecordForm.tsx` のバッジはこの関数を使う。

- 代案：表示のたびに導く。一覧を見ても表示が分からず、仕様の表と照らし合わせにくい。

### 国名の一覧には、i18n-iso-countries にない地域だけを足す

`COUNTRY_NAMES` は i18n-iso-countries の名前に、一覧のうち i18n-iso-countries にないコード（XN・XS）を足してから、日本語名の順に並べる。`XK` は i18n-iso-countries の「コソボ」をそのまま使い、重複させない。検索、名前の参照、候補の並びは既存の仕組みのままで動く。

「北」が漢字のため、ひらがなの「きたきぷろす」は「北キプロス」に一致しない。読みで引けるよう、北キプロスに別名（`COUNTRY_ALIASES`）「キタキプロス」を足す。別名はカタカナで持てば、ひらがなの入力もそろえて一致する。「ソマリランド」は部分一致で引けるので別名を足さない。

### 地図の形状には、`id` がないときに `mapName` で ID を割り当てる

`toMapCountries` は、`id` のない形状について、一覧の `mapName` と `properties.name` が一致すればその `code` を割り当てる。一致しない形状（Indian Ocean Ter.、Siachen Glacier）はこれまでどおり `undefined` のままにする。

`id` がない形状に限って名前で照合するので、ISO のコードがある国の扱いは変わらない。

- 代案：Natural Earth の係争地データなど、別の地図データを足す。今回の3地域は world-atlas にすでに形状があるので必要ない。

## Risks / Trade-offs

- [world-atlas を更新したときに `properties.name` が変わり、地域が塗られなくなる] → 一覧の各地域について `mapName` に一致する形状がちょうど1つあることを単体テストで確かめ、更新したときに気づけるようにする。
- [`XN`・`XS` は外部では共有されていない値で、ほかのアプリやデータとそのままでは突き合わせられない] → この ID は端末内の記録にしか使わず、画面には `--` を出す。割り当ては仕様の一覧で管理する。
- [「XK は地図に形状がない」ことを前提にした既存のテストが成り立たなくなる] → 地図に対応しないコードの例には、ISO の利用者割当範囲で一覧にない `ZZ` などを使うように書き換える。

## Migration Plan

保存形式は変えないので、データの移行は必要ない。この変更の前に記録したコソボ（`XK`）の記録は、そのまま地図で塗られるようになる。元に戻す場合も保存データには触れないので、XN・XS の記録は名前と地図に対応しないコードとして残る（地図に存在しない国コードの扱いの要件により、表示は中断しない）。
