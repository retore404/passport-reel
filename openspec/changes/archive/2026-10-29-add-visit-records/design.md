# Design

## Context

- `apps/web` は Vite + React のフロントエンドのみのアプリで、状態管理ライブラリやルーターは使っていない。
- 地図は `WorldMapCanvas` が `visited: ReadonlySet<string>`（alpha-2）を受け取って描く。現在は `App.tsx` が `sampleVisitedCountries.ts` のサンプルを渡している。
- テストは Vitest で、DOM を使わない純粋なロジック（`src/map/*.test.ts`）だけを対象にしている。
- `i18n-iso-countries` は既に依存にあり、日本語データ（`langs/ja.json`、250 件）を持つ。ただし韓国は「大韓民国」、中国は「中華人民共和国」のように正式名称で、一般的な呼び名では部分一致しない。
- 画面構成は `docs/design-guidelines.md` と、承認済みのモック（スマートフォンは「上に地図、下に一覧、追加はシート」の案 A）に従う。

## Goals / Non-Goals

**Goals:**

- 記録のデータ操作（追加・削除・重複判定・訪問国の集合・年ごとのまとめ・再訪判定）を UI から分離した純粋関数にし、単体テストで仕様のシナリオを確かめられるようにする。
- 記録のデータ形式を、#3（最初に訪れた年の算出）と #8（エクスポート・URL 共有）でそのまま使える単純な形にする。

**Non-Goals:**

- 複数のタブ・ウィンドウ間での記録の同期。
- 記録の編集（年や国の変更）。削除して追加し直す。
- 削除の取り消しと確認ダイアログ。
- プレビュー画面との切り替え（上部バーの切り替えボタン、スマートフォンの下部タブ）。#3 で追加する。

## Decisions

### 記録のデータ形式

`{ year: number; country: string }`（country は alpha-2）の配列とする。記録の同一性は `year` と `country` の組で決まるため、ID は持たない。

- 代替案として、記録ごとに ID を持つ形を検討した。今の仕様には同じ組を区別する場面がないので、ID は不要と判断した。

### 保存形式

localStorage のキー `passport-reel:visit-records` に `{ "version": 1, "records": [...] }` を JSON で保存する。

- `version` を持たせ、将来形式を変えるときに古いデータを読み替えられるようにする。
- 読み込みでは、形式を検証する。型の合わない要素や範囲外の年、重複を除き、その後で使う。JSON として壊れている場合や `version` が未知の場合は、空の記録で開始する。このとき元のデータは、ユーザーが記録を変更するまで上書きしない。
- 書き込みは、記録が変わるたびに全体を保存する（記録は多くても数百件の想定）。
- `localStorage` へのアクセスが例外を投げる環境（プライベートブラウズでの保存拒否など）では、保存できないことを状態として持ち、画面に案内を出す。記録は表示中のメモリ上だけで扱う。

### モジュール構成

`src/records/` に次を置く。

- `visitRecords.ts`：純粋関数。`addRecord`、`removeRecord`、`hasRecord`、`visitedCountries`（alpha-2 の Set）、`groupByYear`（新しい年が先）、`isRevisit`（より前の年に同じ国があるか）を置く。
- `storage.ts`：保存データの解析（`parseStoredRecords`）と、localStorage の読み書きを置く。解析は純粋関数にしてテストする。
- `countryNames.ts`：日本語の国名一覧と検索（`searchCountries`）を置く。
- `useVisitRecords.ts`：React のフック。初回に読み込み、変更のたびに保存し、保存できるかどうかを返す。

`App.tsx` はフックから記録を受け取り、`visitedCountries(records)` を `WorldMapCanvas` に渡す。

- 状態管理ライブラリは使わない。記録を使うのは今のところ記録画面だけなので、`useState` で足りる。

### 国名の検索

- 候補は `i18n-iso-countries` の日本語名を持つ全コードとする。地図に形状がないコード（例：XK）も選べる。地図側は対応しないコードを無視する（`world-map` の既存要件）。
- 入力と国名の両方を同じ規則で正規化してから部分一致させる。規則は、NFKC による全角・半角の統一と、ひらがなからカタカナへの変換である。
- 正式名称と異なる一般的な呼び名は、小さな別名表をコードに持って検索の対象にする。表示には日本語の正式名を使う。別名の対象は少数にとどめる（韓国、北朝鮮、中国、米国、英国、エスワティニなど）。
- 候補の並びは、前方一致を先に、残りを国名順にする。表示は最大 8 件とする。
- 代替案として、`Intl.DisplayNames` を検討した。ブラウザによって表記が変わり、別名も扱えないため採用しない。

### 画面構成

| 幅 | 構成 |
| --- | --- |
| 768px 以上（PC） | 左に幅 360px のパネル（上に入力欄を横並び、下に一覧）、右に地図 |
| 768px 未満（スマートフォン） | 上に地図（高さの約 4 割）、その下に一覧、最下部に「＋ 記録を追加」ボタン。ボタンで下からシートを開き、入力欄を縦に並べる |

- 入力欄のコンポーネントは 1 つにして、PC ではパネルに、スマートフォンではシートの中に置く。
- シートは背後を半透明の黒（`::backdrop`）で覆い、背後のタップ・閉じるボタン・Esc で閉じる。追加後もシートは開いたままにし、国の欄だけを空にして年は残す。続けて同じ年の国を追加しやすくするためである。
- 国の候補はネイティブのボタンの一覧にする。国の欄で↓を押すと候補へフォーカスが移り、↑↓で候補の間を動き、Enter で決定する。追加済みの候補は `disabled` にして「追加済み」と表示する。
  - 代替案として、WAI-ARIA の combobox パターン（`role="listbox"` と `option`）を検討した。lint（jsx-a11y）の意図に合わせ、ロールで部品を自作するよりネイティブ要素を優先して採用しない。
- シートはネイティブの `<dialog>` を `showModal()` で開く。フォーカスの閉じ込めと Esc での閉じる動作をブラウザに任せる。
- 訪問国の数は地図の左下に重ねて表示する。

## Risks / Trade-offs

- [別名表の網羅性] 一般的な呼び名の一部が検索で見つからない → 部分一致で正式名称にも当たるので、実害が大きい国に絞って別名を持つ。見つからない呼び名が分かったら表に追加する。
- [localStorage の消失] ブラウザのデータ削除や Safari の保存期間制限で記録が消える → この変更では対処しない。#8（エクスポート）で持ち出し手段を用意する。
- [複数タブでの上書き] 2 つのタブで同時に編集すると、後から保存したほうが残る → 単一タブでの利用を想定し、Non-Goals とする。

## Migration Plan

- 既存の保存データはないため、移行は不要。
- `sampleVisitedCountries.ts` を削除する。初回表示は記録なしの状態（地図はすべて未訪問の色、一覧は空の案内）になる。
