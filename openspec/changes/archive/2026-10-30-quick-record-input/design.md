# Design

## Context

- 記録の入力欄は `RecordForm` が持ち、PC ではパネルの中で横並び、スマートフォンでは下から出るシート（`Sheet`）の中で縦並びにしている。追加ボタンは選んだ候補（`selected`）があるときだけ押せる。
- 入力欄の文字は本文と同じ 14px。iOS Safari は 16px 未満の入力欄にフォーカスすると画面を拡大する。
- シートは画面の下端に置いた `dialog` で、高さは中身に合わせている（最大 85dvh）。iOS Safari はキーボードを出してもレイアウト上の高さを変えず、見えている範囲（visual viewport）だけを縮めるため、下端に置いた要素はキーボードに隠れる。
- UI のテスト基盤（DOM 環境）はなく、テストは純粋関数のユニットテストで行っている。

## Goals / Non-Goals

**Goals:**
- 唯一の候補の判定と、変換確定の Enter の判定をテストできる純粋関数にする。
- キーボードの位置を追う JS を持たずに、iPhone でキーボード表示中も入力できるようにする。

**Non-Goals:**
- 候補が複数あるときの操作（↓で候補へ移る）は変えない。
- 書き出しのシートの形は変えない。

## Decisions

### 唯一の候補は「選べる候補」から求める
`searchCountries` の結果から、その年に追加済みの国を除いて 1 件だけ残ればその国を唯一の候補とする。追加済みの国は選べない（既存の要件）ため、候補の件数ではなく選べる件数で判定する。追加する国は「選んだ候補」を優先し、なければ唯一の候補とする。追加ボタンもこの国を追加するので、候補を選ばずに押せる。

### Enter はフォームの送信に任せ、変換確定の Enter だけを止める
国の欄は `form` の中にあるため、Enter はフォームの送信（implicit submission）として届き、送信処理で唯一の候補を追加できる。変換確定の Enter は、国の欄の `keydown` で `isComposing` が true か `keyCode` が 229 のときに `preventDefault` して送信させない。Safari は変換確定の Enter の `keydown` を `compositionend` の後に `isComposing=false`・`keyCode=229` で送るため、`isComposing` だけでは判定できない。`keyCode` は非推奨だが、この判定に代わる標準の手段がないため使う。

代替案: `compositionstart`/`compositionend` で入力中かどうかを状態に持つ案は、Safari では `compositionend` が `keydown` より先に来るため同じ問題が残る。

### 拡大は入力欄の文字を 16px にして防ぐ
`.control`（年の選択と国の欄）の文字を 16px にする。PC でも同じ大きさにして、表示幅による分岐を持たない。

代替案: viewport の `maximum-scale=1` は自動の拡大を止められるが、利用者が指で拡大することも妨げるため採用しない。

### キーボード対策は背の高いシートで行う
記録の追加シートは最初から高さ 85dvh で開き、年・国の欄・追加ボタンをシートの上部に置く。国の欄と追加ボタンを横に並べ、候補リストはその下でシートの残りの高さを使ってスクロールさせる。キーボードが出ても隠れるのはシートの下部（候補リストの下側）だけで、入力欄・追加ボタン・候補の先頭が見える。`Sheet` に背の高い形で開く指定を足し、記録の追加シートだけで使う。

代替案: `visualViewport` の大きさと位置からキーボードの上端を求め、シートの下端を合わせる案は見た目がよいが、iOS Safari には visual viewport の resize が届かない・キーボードの動きが終わるまで更新されない・閉じた後に `offsetTop` が戻らない、といった不具合の報告があり、OS の更新ごとに実機での調整が要るため採用しない。

### 国の欄と追加ボタンの並びは PC とスマートフォンで共通にする
国の欄と追加ボタンを 1 つの行にまとめる構造を両方の表示で使い、PC は年の選択との 2 列、スマートフォンは縦並びにする。PC の見た目はほぼ変わらないが、候補リストの幅は追加ボタンの下まで広がる。

## Risks / Trade-offs

- [キーボードを閉じた状態や入力前は、シートの下部が空いて見える] → iPhone では国の欄を選ぶとすぐキーボードが出るため、目立つ場面は少ない。承認済みのモック（#22）で合意した。
- [画面の低い端末（iPhone SE など）では、キーボードの上に見える候補が 2 件程度になる] → 候補リストはスクロールでき、唯一の候補は先頭に出るため、手早い追加は妨げない。
- [`keyCode` 229 の判定は非推奨の API に依る] → 判定を 1 つの関数にまとめ、テストで挙動を固定する。
- [iPhone での見え方はこの開発環境で確認できない] → 実機での確認を手動の確認項目にする。
